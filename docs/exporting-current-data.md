# Exporting a GTNH dataset

The release workflow keeps both ShadowTheAge submodules read-only. Temporary exporter sources, the private NESQL
database, and intermediate packs stay under ignored `.export-work/`; only verified web assets are published.

## Requirements

Use native WSL tools: Node.js/npm, `bash`, `patch`, `unzip`, JDK 8, JDK 17, JDK 21, and the .NET 8 SDK. The exporter
uses its Gradle wrapper; a system Gradle installation is optional. Initialize both upstream repositories with:

```sh
git submodule update --init --recursive
```

## Run the direct export

The normal path downloads the reviewed official archive, verifies its byte size
and SHA-256, prepares a disposable client, launches the embedded GTNH/Forge main
class under Xvfb, creates an integrated creative world, waits for NEI, normalizes
Thaumcraft research and warp, exports, and processes the result:

```sh
npm run export:direct -- --version 2.9.0-beta-2
```

To reuse a previously downloaded archive, supply it explicitly; it is still
verified against the profile before preparation:

```sh
npm run export:direct -- \
  --version 2.9.0-beta-2 \
  --archive ./GT_New_Horizons_2.9.0-beta-2_Java_17-25.zip
```

No launcher installation or account is required. The direct resolver reads the
ordered component patches, libraries, native classifiers, launch arguments, and
asset index embedded in the official client archive. It uses a deterministic
offline identity and never opens an existing player instance.

The command refuses to reuse its disposable work directory. Launcher,
in-client exporter, and orchestration status are separate JSON files under
`.export-work/direct-export-cache/status/`; inspect all three on failure. A JVM
exit is not success unless the in-client controller reached `complete` and the
processor subsequently wrote and verified `process-result.json`.

Preparation still remains available as a diagnostic primitive with
`npm run export:prepare`, and `npm run export:runtime -- --dry-run` can emit the
resolved JVM launch plan. They are not manual release checkpoints.

## Process, verify, and publish

```sh
npm run export:publish -- \
  --pack .export-work/2.9.0-beta-2-direct/pack \
  --mode stage

npm run check
npm test
npm run build
```

Processing validates the patched NESQL schema, uses the pinned local 2.8 format-v5 fixture for obsolete remaps,
applies the browser catalog retention policy, builds the pack twice, compares every generated byte, and verifies
hashes plus sampled sprites. Missing NBT-specific renders abort atlas generation rather than becoming transparent
icons. Stage and deploy the immutable directory without changing `versions.json`, then verify
every deployed asset:

```sh
npm run smoke:deploy -- \
  https://<site>.netlify.app/ \
  --manifest data/<dataset-id>/pack-manifest.json \
  --all-assets
```

Only after that succeeds, activate the already staged bytes and deploy the small index change:

```sh
npm run export:publish -- \
  --pack .export-work/2.9.0-beta-2-direct/pack \
  --mode activate
```

The current browser-complete run produced dataset `2.9.0-beta-2-racad91e7243b`. Its provenance is stored beside
the manifest under `public/data/2.9.0-beta-2-racad91e7243b/`. It retains recipe-connected configurable tools and
other families that ShadowTheAge intentionally excludes from its calculator; see
[`browser-catalog-policy.md`](browser-catalog-policy.md).

Deploy the app and run `npm run smoke:deploy -- https://<site>.netlify.app/` before considering the new version
released. Existing users retain their explicitly active installed dataset; the first index entry is only the
default for users without an active selection.
